# zapret2-discord-youtube

Сборка [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube), перенесённая на движок
[bol-van/zapret2](https://github.com/bol-van/zapret2) (`winws2.exe`). Репозиторий сам следит за обоими апстримами
и публикует новый релиз, когда выходит новая версия любого из них.

## Использование
1. Скачайте архив из [Releases](../../releases/latest) и распакуйте в папку без кириллицы и пробелов.
2. Запускайте `general2*.bat` от администратора, либо установите службу через `service.bat`.
3. `service.bat` → пункт 10 (Check for Updates) и пункт 6 (автопроверка) сравнивают версию с этим репозиторием.

Версия имеет вид `<Flowseal>_zapret2-<zapret2>`, например `1.10.3_zapret2-1.0.5.2`.

## Как работает автообновление
Workflow `.github/workflows/sync-upstream.yml` запускается каждые 6 часов (и вручную в разделе Actions):

1. Узнаёт последние релизы Flowseal и zapret2. Если версии отличаются от `.service/upstream.json`, начинается пересборка.
2. Скачивает Flowseal нужной версии и **заново конвертирует** все `general*.bat` в `general2*.bat` (`tools/convert.py`),
   патчит `service.bat` (`tools/patches.py`), берёт `winws2.exe`, WinDivert и Lua из релиза zapret2
   (контрольные суммы сверяются с `sha256sum.txt` релиза).
3. Собирает `nfqws2` той же версии и **проверяет каждую стратегию** (`tools/validate.py`): командная строка, которую получит служба,
   отдаётся настоящему движку. Если хоть одна стратегия не принята, ничего не публикуется.
4. Коммитит результат в `main` и создаёт релиз с архивом и `sha256sum.txt`.
5. Всегда, независимо от релизов, подтягивает `.service/hosts`, `.service/ipset-service.txt` и `lists/ipset-all.txt.backup`
   из `main` Flowseal: он обновляет их между релизами, а пункты 8 и 9 меню скачивают их из вашего репозитория.

При сбое (апстрим изменил формат, не нашлась точка патча, не прошла валидация) открывается issue с логом; релиз не создаётся.

### Первый запуск
1. Загрузите содержимое репозитория на GitHub (ветка `main`, репозиторий публичный: клиенты читают `raw.githubusercontent.com`).
2. Вкладка **Actions**: включите workflows, если GitHub предложит.
3. **Actions → Sync upstream → Run workflow**. Первый запуск пересоберёт сборку под имя вашего репозитория
   (в `service.bat` прописываются ваши адреса обновлений) и создаст первый релиз.

### Ручное управление
| Что нужно | Как |
|---|---|
| Пересобрать и переопубликовать | Run workflow → `force` |
| Выпустить релиз после правки `tools/` без смены апстрима | Run workflow → `rev_bump` (версия получит суффикс `-r1`, `-r2`, …) |
| Проверить локально | `python3 -m unittest discover -s tools -p 'test_*.py'` |

## Что здесь чьё
`bin\*.bin`, `lists\`, `utils\` (кроме `install_service.ps1`) и исходные стратегии принадлежат Flowseal, движок и Lua принадлежат
bol-van. Лицензии лежат в `licenses\`. Файлы `tools\`, `utils\install_service.ps1` и workflow написаны для этого порта.

## Ограничения
- Пересборка идёт только по **релизам** апстримов, а не по каждому коммиту, кроме двух списков из п. 5.
- Служба хранит порты Game Filter, с которыми была установлена: после переключения пункта 4 переустановите службу (пункт 1).
- Скрипты проверены на Linux-сборке `nfqws2` и PowerShell 7; на живом трафике Windows их проверяете вы.
